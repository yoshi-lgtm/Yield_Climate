# パネルの2000–2023への拡張と、識別の限界

**作成日：2026年9月18日**
**対象：`phenology_calibrated_2026-09.md` §7-1「標本を1993–2020に戻す」の実施**
**標本：関東6都県・2000–2023・209市町村・4,588行**（従来の2,321行／12年から倍増）

---

## 0. 要約

前稿は「$\delta$ の識別が2010年1年に依存している。期間を伸ばして極端年を増やすことが唯一の直接的な対処」と結論した。**この処方は効かなかった。**

| 論点 | 結論 |
|---|---|
| 期間は伸ばせたか | **2000–2023の24年に拡張**（出穂期・収量・気象すべて実測で埋まった） |
| 極端年は増えたか | **増えた**。2023年は heat_old 26.6日と24年で最も暑い（2010年は18.9日） |
| 識別は改善したか | **改善しなかった**。leave-one-year-out 24通りのうち、依然として**2010年を抜いたときだけ**係数が消える |
| なぜか | **2023年は2010年と同等の高温だったのに収量が落ちなかった**（514.7 vs 484.2、平年超） |
| 何が起きているか | **高温感応度そのものが時間とともに縮小している**。同一191市町村の断面で、高heat群と低heat群の収量差は 2010年 -67.9 → 2023年 -23.8 |
| 登熟期ベース heat の優位 | **24年でも維持**。現行指標の3.6倍の説明力（ΔR² 0.066 vs 0.018） |

核心：**問題は「極端年が足りない」ことではなく、「被害関数が定常でない」こと。** 冷夏年（2003・2006）では heat の係数が**正**になり、2010年以降は負の係数が縮小し続けている。単一の線形 $\beta$ を24年でプールすることは、符号の異なる年効果を平均しているにすぎない。

## 5. なぜ期間延長が効かなかったのか

### 5.1 2023年は2010年より暑かったが、収量は落ちなかった

| year | 実測登熟期HD35 | 現行heat(7-8月HD34) | 収量 | 出穂日 |
|---|---|---|---|---|
| **2003** | 0.9 | 3.5 | **463.7**（最低） | 224.1 |
| 2006 | 0.4 | 4.6 | 479.0 | 222.2 |
| **2010** | **9.7** | 18.9 | **484.2** | 216.6 |
| 2018 | 5.5 | 21.8 | 510.1 | 212.1 |
| 2020 | 7.3 | 13.7 | 508.4 | 217.8 |
| **2023** | **9.5** | **26.6**（最高） | **514.7** | 211.4 |

2023年は現行指標で24年中もっとも暑く、登熟期HD35でも2010年とほぼ同じ（9.5 vs 9.7）。にもかかわらず**収量は514.7で平年を上回った**。

一方、24年で収量が最も低かったのは**2003年（463.7）で、これは冷夏**である。

**「極端年を増やせば識別が改善する」という期待が外れたのは、追加された極端年（2023）が収量を落とさなかったからである。**

## 6. 前稿の処方の撤回

`phenology_calibrated_2026-09.md` §6 は次のように書いた：

> **期間を伸ばすこと（1993–2008を含める）が、この制約への唯一の直接的な対処**である。1993年（冷夏）・1994年（記録的猛暑）・2010年と極端年が複数入る。

**これを撤回する。** 2000–2023へ拡張して極端年（2023年は2010年より暑い）を追加したが、識別構造は変わらなかった。理由は §5.1 のとおり、追加された高温年に収量被害が出なかったためである。

1993–1999 にさらに遡っても同じ問題が残る可能性が高い。1993年は冷夏で、レビュー §4.3 が既に「1993年を除外するだけで $\hat\delta$ が半減する」と報告している。つまり**極端年を足すたびに「その年に依存した推定値」が1つ増えるだけ**で、共通の $\delta$ が精度よく推定されるわけではない。

## 7. 研究への含意

| 条件 | 状態 |
|---|---|
| $\hat\beta<0$（IVの**関連性**） | **成立するが非定常**。2010年を抜くと -0.0040 → -0.0013、2015年以降はほぼゼロ |
| $\hat\delta>0$（IVの**除外制約**） | **未確認**。24年でも2010年を抜けば消える |

問題の所在が3段階で移動した：

1. 当初：**$\hat\delta<0$ という理論と逆の符号**（→ 期間プールの人工物だった）
2. 前稿：**heat の測定が悪い**（→ 実測出穂期で解決、within R² 0.025 → 0.208）
3. 本稿：**被害関数が定常でない**

3は測定でもデータ量でも解決しない。単一の $\beta$・$\delta$ を24年でプールする定式化そのものが、研究設計として妥当かを問い直す必要がある。

### 修論の識別戦略への影響

`heat × 圃場整備率` を除外制約付きIVとして使う構想は、$\delta$ が「特定の1年にしか現れない」のであれば成立が苦しい。考えうる方向：

- **2010年を分析対象イベントとして正面から扱う**。24年パネルで平均効果を追うのではなく、2010年の高温ショックに対する被害の異質性（整備率別）を推定する準実験として設計しなおす。実質的にそこでしか識別されていない以上、これが最も誠実
- **適応を研究対象にする**。「高温害の感応度がなぜ2010年以降に縮小したか」（品種転換・作期移動・水管理）は、それ自体が農業経済学の問いとして成立する。§1.2 の出穂日5〜8日前倒しは作期移動の直接的な証拠になりうる
- **被害関数の非定常性を明示的にモデル化する**。$\beta_t$ の時間変化を推定し、整備率との交互作用をその中で評価する

### 9.3 interactive fixed effects について

`analysis.py` 末尾の拡張案にある interactive fixed effects (IFE) を検討した。

**fixest は IFE を実装していない。** fixest が持つのは高次元固定効果・IV・クラスターSE・`fe[slope]` 形式の varying slopes まで。Bai (2009) 型の因子構造 $\lambda_i' f_t$ には `phtt`（Bai (2009) そのもの、因子数の情報量規準つき）、`gsynth`（Xu 2017、EM＋CVで因子数選択、不完備パネル可）、`fect`（Liu-Wang-Xu 2022）のいずれかが要る。

**ただし本稿の結果を踏まえると、IFE には構造的な問題がある。**

$$y_{it} = \alpha_i + \gamma_t + \lambda_i' f_t + \beta\,\text{heat}_{it} + \delta\,\text{heat}_{it}\times\text{consol}_i + \varepsilon_{it}$$

$\lambda_i' f_t$ は「共通ショックに対する市町村ごとの反応の異質性」を吸収する項である。しかし §4・§5 で明らかになったのは、

- $\beta$ の大部分は2010年という**単一の共通ショック**から来ている
- $\delta$ は「2010年に整備率の高い市町村ほど被害が小さかった」という、**まさにそのショックへの反応の異質性**

つまり $\delta$ が捉えたい効果と IFE が除去しようとする $\lambda_i' f_t$ が、構造的にほぼ同じ対象を指している。`consol30` が $\lambda_i$ と相関していれば（平野部ほど整備率が高く気候曝露も異なる、という形で十分ありうる）、IFE は $\delta$ を丸ごと吸収する。

したがって **「IFEで $\delta$ が消えた」という結果は情報量がほぼゼロ**になりかねない。逆に**残れば非常に強い証拠**になる。実施する場合は、因子数 $r$ を1・2・3と振って係数の推移を示し、消えた場合に何を主張しないかを事前に決めておくべきである。位置づけは推定の本体ではなく頑健性の章。

### 9.4 パス依存の注意点

`04yield_data_kanto_debuged.py` の出力先は

```python
DATA_DIR  = Path(os.environ.get("YIELD_DATA_DIR", "."))   # 環境変数は未設定 → Path(".")
YIELD_DIR = DATA_DIR / "yield"                            # → ./yield/
```

で、**環境変数 `YIELD_DATA_DIR` は設定されていない**。つまりカレントディレクトリ依存であり、リポジトリルート（`Yield_Climate/`）以外から実行すると、そこに空の `yield/` が新規作成され（`mkdir(parents=True, exist_ok=True)`）、`api_data_*.csv` が無いと判断されて再ダウンロードが走る。**実行は必ずリポジトリルートから行うか、`YIELD_DATA_DIR` を明示すること。**

同様に `03c` / `09` / `10` も相対パス前提（`./avg_temp_fixed/`、`./results/` 等）。

なお `ESTAT_APPID` は環境変数に平文で設定されている。コード側は環境変数参照でコミットはされない作りだが、取り扱いには注意。
