## 0. 要約

レビューが残した最重要課題は「heat の測定」だった（within R² = 0.025）。GDD積算で出穂日を推定し、登熟期の気象変数を構築しなおした結果：

| 論点 | 結論 |
|---|---|
| 出穂日は推定できたか | **可能**。平年 7/31、県別 7/26（千葉）〜8/9（群馬） |
| 登熟期ベースの heat は現行より良いか | **窓の長さ次第**。登熟40日は大幅に改善、登熟20日は現行より**悪い** |
| within R² はどこまで上がったか | 0.025（元）→ 0.077（現行heat・2009+）→ **0.153**（登熟40日の気温ビン） |
| $\hat\beta<0$ は頑健か | **是**。全指標・全スペックで有意に負 |
| $\hat\delta$（heat × 圃場整備率）は | **heat の定義に対して頑健でない**。最良スペックでは符号が理論どおり正になるが有意でない |

## 2. 出穂日の推定

### 2.1 手法

$$\text{GDD}_{it} = \sum_{\tau=\text{移植日}_i}^{t} \max(T^{mea}_{i\tau} - 10,\ 0),\qquad t^*_{it} = \min\{t : \text{GDD}_{it} \ge 1000\}$$

移植日は都県単位の仮定（千葉 4/25、茨城 5/5、栃木・神奈川 5/10、埼玉・東京 5/15、群馬 5/20）。

GDD閾値 1000 は**文献値をそのまま当てたのではなく、推定される県別平年出穂日が関東のコシヒカリの出穂期に整合するようキャリブレーションした**（§6 で感度分析）。

| GDD閾値 | 7都県平均 出穂日 |
|---|---|
| 800 | 7/18 |
| 900 | 7/25 |
| **1000** | **7/31** |
| 1100 | 8/6 |

## 3. heat 指標の horse race

### 3.1 公正な比較の作り方

指標ごとに「その窓の GSR/APCP」をコントロールに使うと、within R² の差が heat 指標の差なのかコントロールの差なのか分離できない。ここでは**コントロールを `GSR_78`, `APCP_78` に固定し、heat 変数だけを入れ替える**。コントロールのみの模型の within R² = 0.0213 が比較基準。

4. 年次窓と平年窓の差は小さい（0.1006 vs 0.0939）。**窓を内生化しなくてもほとんど失われない**（§5.1 参照）。

## 4. 気温ビン推定（Schlenker & Roberts 2009型）

### 4.1 構築

日最低 $T^{min}$・日最高 $T^{max}$ の間を正弦カーブとみなし、各気温ビンの滞在時間（日換算）を求める。閾値 $c$ 超過時間は

$$\text{frac}(c) = \frac{1}{2} - \frac{1}{\pi}\arcsin\!\left(\frac{c-M}{W}\right),\quad M=\frac{T^{max}+T^{min}}{2},\ W=\frac{T^{max}-T^{min}}{2}$$

で、ビン滞在時間はこれの階差。数値積分と照合して誤差 1e-5 以下、ビン合計はちょうど1日になることを確認済み。

**`TMP_min` は既存の市町村データに存在しなかった**（`03calculate_all_def_debuged.py` の `target_weather` から漏れていた）。メッシュのnetCDF（`MetData_Output/TMP_min/`、8.2GB・46年分）は揃っていたので、03と同一の重みで 2009–2020 分を構築した（`03b_add_tmp_min.py`）。

- 32–34 の +0.0039\*\*\* は 34–36 との対比で生じている可能性が高く、単独では解釈しない。

## 5. 交差項の再検証

### 5.1 「窓の内生性」について

年次窓（$t^*_{it}$ がその年の気象で決まる）は、露出窓自体が気象ショックに依存するため厳密には内生。そこで市町村ごとの**平年出穂日**を使う版（`cl_` 接頭辞）を並行して構築した。§3.2 のとおり両者の説明力差は小さく、**因果的主張をするなら平年窓を基準にしてよい**。

### 5.2 heat × 圃場整備率

各 heat 指標のもとで `heat × consol30` を推定し、**平均 heat で評価した consol30 0→100% の収量効果**に換算：

| heat の定義 | 交差項 | SE | | 効果（平均heatで評価） | 95%CI |
|---|---|---|---|---|---|
| 現行 7-8月 HD34 | +0.00025 | 0.00041 | | +0.30% | [-0.69%, +1.29%] |
| **登熟40日 HDD26** | **+0.00023** | 0.00016 | | **+0.94%** | [-0.32%, +2.19%] |
| 登熟40日 HD35 | +0.00109 | 0.00079 | | +0.55% | [-0.23%, +1.32%] |
| 登熟20日 HDD26 | **-0.00037** | 0.00016 | \*\* | **-0.96%** | [-1.76%, -0.16%] |
| 登熟20日（平年窓）HDD26 | -0.00027 | 0.00015 | \* | -0.70% | [-1.46%, +0.06%] |

**交差項の符号は heat の定義に依存して反転する。**

- 説明力の高い指標（登熟40日）では**符号が理論どおり正**になるが、統計的にゼロと区別できない
- 説明力の低い指標（登熟20日）では**有意に負**（理論と逆）

登熟20日で負の有意な交差項が出るのは、測定誤差の大きい heat に交差項が誤差を吸収させている可能性が高い。**説明力の高い指標を優先すべきで、そのときの結論は「符号は理論どおり正、ただし有意でない」。**

### 5.3 3変数同時投入（horse race）

登熟40日 HDD26 のもとで：

| | 係数 | SE |

| heat | -0.00153\*\*\* | 0.00019 |

**3つとも符号は正（緩和方向）だが、いずれも有意でない。** within R² = 0.1047。

## 7. 発見した実装上の問題

### 7.1 `TMP_min` が市町村データに存在しなかった

`03calculate_all_def_debuged.py`

```python

```


は `NaN >= 34` → `False` となるため、**これらの市町村の `heat` は欠測ではなく 0 として `kanto.csv` に入っている**。現状の推定は `GSR`（こちらはNaN）経由で行が落ちているため実害が出ていないが、GSRを外したスペックでは「高温日数ゼロの市町村」が7つ紛れ込む。

## 8. 研究への含意

| 条件 | 状態 |
|---|---|
| $\hat\beta<0$（気象ショックIVの**関連性**） | **成立**。全指標・全スペックで有意に負。登熟40日HD35で -0.0048\*\*\* |
| $\hat\delta>0$（`heat × 圃場整備率` IVの**除外制約**） | **未確認**。最良スペックで符号は理論どおり正、有意でない |

レビューが残した問い「heat をきちんと測ったうえでも $\delta$ はゼロか」への現時点の答え：

> **heat の説明力は 0.025 → 0.153 まで6倍に改善した。そのうえで $\delta$ はやはりゼロと区別できない。ただし符号はレビュー時点の「理論と逆」から「理論どおり正」に変わり、仮定を振っても正のまま安定している。**

これは「説明のつかない逆符号」でも「頑健な緩和効果」でもなく、**符号は理論と整合するが検出力が足りない**状態。標本は201市町村×12年しかなく、consol30 の識別は市町村間の差のみ（時間不変）に依存しているため、この検出力は構造的な制約である可能性が高い。

登熟40日HDD26で評価した効果は **+0.94%（95%CI [-0.32%, +2.19%]）**。「圃場整備率が0%から100%に上がると、平年並みの高温年で収量が0.9%改善する（ただし-0.3%〜+2.2%の範囲）」というのが、現時点で言える最も強い主張。

### 窓の選択について

レビュー §9 の「閾値の選択」と同じ問題が窓にも起きる。同一データで窓を選んでから同一データで $\beta,\delta$ を検定すると信頼区間が正しくない。落とし所：

- **ベースラインの窓は農学文献から取る**（登熟期＝出穂後40日、または出穂後20日）
- グリッドサーチ版は頑健性として併記し、「データが選んだ窓」であることを明示する
- あるいは前半（2009–2014）で窓を選び、後半（2015–2020）で検定する
