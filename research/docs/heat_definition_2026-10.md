# 現行設計における `heat` の定義：構築の鎖と定式化の確認

**作成日：2026年10月13日**
**目的**：推定式に入っている熱指標が正確に何であるかを、記憶ではなくコードとデータから特定し記録する。あわせて文書と実装の食い違いを明示する。
**根拠**：`research/model/estimate.R`、`research/model/omega_decomposition.R`、`research/model/t12_vcov.R`、`Data_cleaning/03c_rebuild_weather_nanfix.py`、`Data_cleaning/06phenology_heat.py`、`Data_cleaning/08phenology_calibrated.py`、`Data_cleaning/09phenology_anchored.py`、`research/model/kanto_panel_2000_2023.csv`

## 1. 結論

現行の `heat` は **`obs_HD35`＝実測登熟期窓における日最高気温 35.0℃以上の日数**である。

- **水準**であって、市町村平均からの正偏差 $H^{+}$ ではない
- **日数**であって、度日（degree-day）でも期間平均気温でもない
- 窓は**実測出穂期にアンカーした推定出穂日**から始まり、長さは**都県別の実測登熟日数**（43〜62日）

T11・T12 で報告したすべての数値はこの水準スペックの結果である。

## 2. 構築の鎖（6段）

| 段 | 内容 | スクリプト |
|---|---|---|
| 1 | メッシュ農業気象データ（農研機構・1kmメッシュ・日次）の `TMP_max` | — |
| 2 | 市町村別に**田面積加重平均**。NaN ピクセルは重みから外し時点ごとに再正規化（最小有効面積比 0.967） | `03c_rebuild_weather_nanfix.py` |
| 3 | 移植日から **GDD(base 10)** を積算し**都県別閾値**（基準 1000℃日）で出穂日を推定。移植日は実測の都県×年田植期（2009–13年は都県別平年値で外挿） | `08phenology_calibrated.py` |
| 4 | 都県×年の平均出穂日を**実測出穂期にアンカー**（オフセット絶対値の平均 1.61日） | `09phenology_anchored.py` |
| 5 | 窓 $=[\text{heading\_doy},\ \text{heading\_doy}+\text{obs\_n\_days})$。登熟日数は**都県別の定数** | 同 |
| 6 | 窓内で $\sum_{d\in W}\mathbb{1}[T^{max}_d \ge 35.0]$ | `06phenology_heat.py:208, 221` |

第6段の実装は次の2行である。

```
w["hd35"] = (w["TMP_max"] >= 35.0).astype(float)      # :208
... HD35=("hd35", "sum") ...                           # :221
```

したがって `obs_HD35` は**0以上の整数値をとる日数**であり、35℃をどれだけ超えたかの情報は持たない。

### 窓の長さ（`obs_n_days`、都県内で定数）

| 都県 | 登熟日数 |
|---|---|
| 千葉 | 43 |
| 茨城 | 47 |
| 埼玉 | 47 |
| 神奈川 | 51 |
| 栃木 | 54 |

平均 49.3日。窓の長さが都県間で 1.44 倍違うため、`obs_HD35` は**都県間で単位が揃っていない**（同じ暑さでも窓が長い群馬の方が日数が増えうる）。市町村固定効果が水準差を吸収するので係数の識別には影響しないが、記述統計を都県横断で比べるときは注意が必要である。

## 3. 記述統計

パネル `kanto_panel_2000_2023.csv` は 4,588 行（209市町村 × 24年のうち欠損除き）。`obs_HD35` に 4件の欠損があり、**推定標本は 4,584 行**である。

| 統計量 | 値 |
|---|---|
| 平均 | 3.087 日 |
| 標準偏差 | 4.433 |
| 中央値 | **1 日** |
| 最大 | 32 日 |
| ゼロの割合 | **37.1%** |
| within（市町村内）SD | 3.774 |
| between（市町村間）SD | 2.284 |

**分散分解**：都県×年の平均で説明される分が **58.8%**、残差（都県×年内の市町村間変動）が 41.2%（SD 2.847）。

この分解は推論の設計に直結する。処置変動の約6割は都県×年で共通なので、

- 都県×年固定効果を入れると処置変動の 58.8% が消える（T12 の残作業で確認予定）
- 市町村クラスター（G=209）は、実質的に 6 都県 × 24 年の共通ショックを独立扱いしている可能性がある。これが `vcov_inference_T12.md` で Conley 空間 HAC と Ibragimov–Müller を並べた理由である

**ゼロが 37.1%、中央値 1 日**という分布も重要である。被害関数が「ほとんどの観測で処置がゼロ」の設計になっており、$\omega_t$ が極端年に集中する機械的な理由がここにある。

### 2010年と2023年

| 年 | `obs_HD35` 平均 |
|---|---|
| 2010 | 9.673 |
| 2023 | 9.502 |

G0 の予想（$\omega_{2010}\approx\omega_{2023}$）の前提となる数値。実測の重みは 0.359 対 0.286 で、$\delta_t$ の比は 28.7 倍だった（`omega_decomposition_T11.md`）。

## 4. 推定式に入る正確な形

```r
HEAT <- "obs_HD35"
CTRL <- c("GSR_78", "APCP_78")
d[, h_consol := get(HEAT) * consol30]

feols(log_yield ~ obs_HD35 + h_consol + GSR_78 + APCP_78 | city_id + year,
      data = d, cluster = ~city_id, fixef.rm = "none", ssc = ssc(K.fixef = "full"))
```

すなわち

$$\ln y_{it} = \alpha_i + \tau_t + \beta\,\text{HD35}_{it} + \delta\,(\text{HD35}_{it}\times c_i) + \gamma' X_{it} + \varepsilon_{it}$$

- $c_i$ = `consol30`（時間固定、平均 0.367、SD 0.351）
- $X_{it}$ = `GSR_78`（7–8月日射）、`APCP_78`（7–8月降水）
- 固定効果：市町村 + 年（都県×年ではない）
- SE：市町村クラスター、$\text{ssc}(K.\text{fixef}=\text{"full"})$、`fixef.rm = "none"`

`estimate.R:31`、`omega_decomposition.R:37`、`t12_vcov.R:31` の3本すべてで `HEAT <- "obs_HD35"` であり、交差項の作り方も同一である。**実行済みの推定は全部この定式化**である。

## 5. 文書と実装の食い違い（要判断）

### (1) 文書は $H^{+}$、実装は水準

`goals_and_todo.md` の G0（125・127・129行）と T4 の主軸式（144・216行）、`research_portfolio_summary.md` の $\omega_t$ 節（114・129行）は、処置を

$$D_{it}\equiv H^{+}_{it}\cdot c_i,\qquad H^{+}_{it}=\max(\text{heat}_{it}-\bar h_i,\ 0)$$

と書いている。しかし**実行されたのは水準 `obs_HD35` である**。$H^{+}$ を構成しているのは `surprise_decomposition.R`（T1 の副産物分析）だけで、T11・T12 では一度も使っていない。

T11・T12 の結果文書（`omega_decomposition_T11.md`、`vcov_inference_T12.md`）は `h_consol` 表記で水準として書かれているのでコードと整合している。**Goal 側の式だけが先走っていた**（G0 を書いた時点で非対称スペック（T10）を主軸に据える前提だったため）。

**含意**：

- 報告済みの $\omega_{2010}=0.359$、$\delta_{2010}=+0.00356$、汚染項 $-18.5\%$、$\chi^2(23)=98.4$ は**すべて水準スペックの結果**である
- $H^{+}$ 版は未実施（T10 の残作業）
- 2010年の係数は折り畳みでほぼ変わらないと見込まれるが、**$\omega_t$ と他年の $\delta_t$ は変わる**（$H^{+}$ はゼロ近傍の年の処置変動を潰すため、重みはさらに極端年に集中するはず）

**判断が必要**：どちらを本番スペックにするか。選択肢は(a) 水準のままにして文書の式を修正する、(b) $H^{+}$ で T11・T12 を再計算する、(c) 水準を本番にし $H^{+}$ を頑健性に置く。(c) が主結果の性格（恒等式に基づく分解なのでスペックに依存しない）と整合的で、かつ T10 を頑健性として回収できる。

### (2) heat は窓ベースなのにコントロールは固定暦月

`GSR_78`・`APCP_78` は **7–8月固定暦月**である。窓ベースの `obs_GSR_rip`・`obs_APCP_rip` がパネルに存在するのに使っていない。相関は **0.629**（日射）、**0.597**（降水）で別物である。

horse race（`panel_extension_2000_2023.md` §3）では「heat 指標の差だけを見る」ためにコントロールを固定暦月で揃えたのは正しい判断だった。しかし**本番スペックで固定暦月を使い続ける理由はない**。「固定暦月の窓は出穂期のずれで測定誤差を生む」という本研究自身の主張が、日射・降水にもそのまま当てはまる。審査で突かれやすい箇所である。

**判断が必要**：コントロールを `obs_GSR_rip`・`obs_APCP_rip` に替えるか。係数が動かなければ頑健性表の1行で済む。

## 6. パネルにある熱指標の在庫

窓が4種類 × 指標13本。

| 接頭辞 | 窓 |
|---|---|
| `obs_` | 実測登熟期（出穂日 + 都県別実測登熟日数 43–62日）← **現行** |
| `c20_` | アンカー出穂日から 20日固定 |
| `c40_` | アンカー出穂日から 40日固定 |
| `c50_` | アンカー出穂日から 50日固定 |

各窓の指標：`n_days`、`T_rip`、`Tmax_rip`、`Tmin_rip`、`HDD26`、`HDD27`、`CDD20`、`HD33`、`HD34`、`HD35`、`NIGHT26`、`GSR_rip`、`APCP_rip`。

気温ビンは `obs_bin_*` と `c50_bin_*` の各15本（`below_12`、`12_14`〜`36_38`、`38plus`）。

旧指標：`heat_old`（7–8月の HD34）、`T_78`（7–8月平均気温）、`GSR_78`、`APCP_78`。

## 7. 本文での書き方

熱指標の定義は、以下を明示する必要がある。

1. **日数であること**（超過度合いを捨てていること）。これは `HDD26`・`HDD27` との対比で正当化する（horse race で HD35 が勝った事実）
2. **窓が推定＋アンカーであること**。推定出穂日をそのまま使うのではなく、都県×年の実測出穂期に平行移動していること（オフセット絶対値の平均 1.61日）
3. **窓の長さが都県別定数であること**。年による伸縮はしていないので、登熟期間の年次変動は捉えていない
4. **ゼロが 37.1%、中央値 1 日**であること。$\omega_t$ の極端年集中はこの分布の帰結である
5. **都県×年で処置変動の 58.8%** が説明されること。推論方式の選択の根拠になる
