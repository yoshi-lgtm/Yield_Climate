## 0. 要約

進捗報告で「想定と逆」として報告した $\hat\delta<0$（圃場整備率が高いほど高温の悪影響が大きい）は、**期間をプールしたことによる人工物**であり、頑健な発見ではなかった。期間を分割すると符号が反転し、近代期（2009–2020）では統計的にゼロと区別できない。

一方、$\hat\beta<0$（高温が収量を下げる）はすべてのスペック・期間で頑健。

また、`paddy_ratio` は**圃場整備率ではなく水田率**（農用地に占める田の割合）であり、理論が想定する変数と推定している変数が対応していなかった。農林業センサス農業集落カードから真の圃場整備率を構築し、両者を同時に投入する horse race を実施した。

| 論点 | 結論 |
|---|---|
| $\hat\delta<0$ は頑健か | **否**。1993–2000に牽引された期間プールの人工物 |
| $\hat\beta<0$ は頑健か | **是**。-0.0013〜-0.0032（対数、全スペック） |
| `paddy_ratio` の正体 | 水田率（田/農用地）。圃場整備率ではない |
| 圃場整備率は構築可能か | **可能**。センサスGA0001から関東7都県分を構築済み |
| 圃場整備率の交差項 | 近代期で非有意（符号は理論どおり正） |
| 残された最重要課題 | **heat の定義**（within R² = 0.025 と極端に低い） |

## 2. 実装上の問題

### 2.1 標準誤差が未調整だった

```python
# analysis.py
model_fe = PanelOLS(y, X, entity_effects=True, time_effects=True)
res_fe = model_fe.fit()          # cov_type 未指定 → 'unadjusted'
```

`linearmodels` の `fit()` はデフォルトで均一分散SE。系列相関・空間相関ともに未調整のまま。スライド §5 の `***` と F=53.68 はこの前提に立つ。`model.R` は `cluster = ~city_id` を指定しているため、移行によりSEは変わる。

**対処**：`fit(cov_type='clustered', cluster_entity=True)` を使用。本レビューの推定はすべてクラスターSE。

### 2.2 スライドの記述と実装の不一致

| スライドの記述 | 実装 |
|---|---|
| 「市町村×年固定効果」 | `entity_effects=True, time_effects=True` = **TWFE**（市町村FE＋年FE） |
| n=8,613、1993–2020 | `analysis.py` は全期間。`model.R` は `year >= 2009` に限定（n≈2,900） |
| X = GSR, APCP, TMP_mea | `model.R` は **TMP_mea を含まない** |

`model.R` で TMP_mea を落としたため、GSR が気温チャネルを代理している疑いがある（後述 §4.4）。

### 2.3 設計文書と実装の不一致

### 2.5 `paddy_ratio` は時間不変ではない

`03calculate_all_def_debuged.py:279-284` は年ごとに水田率を計算しており、2009年以降のサブサンプルで **269市町村中245市町村**に within 変動がある。

## 3. `paddy_ratio` の正体

`Data_cleaning/03calculate_all_def_debuged.py:279-284`

```python
def calculate_paddy_area(valid_city_id, valid_area, total_valid_city_id, total_valid_area):
    df_paddy = pd.DataFrame({'city_id': valid_city_id, 'area': valid_area})
    paddy_sum_by_city = df_paddy.groupby('city_id')['area'].sum()      # 田
    df_total = pd.DataFrame({'city_id': total_valid_city_id, 'area': total_valid_area})
    total_sum_by_city = df_total.groupby('city_id')['area'].sum()      # 田 + 他農用地
    return paddy_sum_by_city / total_sum_by_city
```

$$\text{paddy\_ratio}_i = \frac{\text{田面積}_i}{\text{田面積}_i + \text{他農用地面積}_i}$$

すなわち **農用地に占める田の割合（水田率）** であり、圃場整備率（区画整理済面積の割合）とは別物。

スライド §2 が提示する $\delta>0$ のメカニズム（用排水インフラ → 冷水掛け流し・深水かんがい → 水温低下 → 高温害緩和）は圃場整備率についての議論であり、水田率には適用できない。同様に §3 の修論への接続（$\hat\delta>0$ が `heat × 圃場整備率` IV の除外制約の農学的根拠）も、水田率では成立しない。

断面相関を見ると、水田率は「暑さ」ではなく「土地の良し悪し」を拾っている：

| | paddy_ratio との相関 |
|---|---|
| yield | **+0.445** |
| heat | +0.002 |
| TMP_mea | +0.155 |

## 4. 主要な推定結果

すべて $\ln(\text{yield})$、TWFE（市町村FE＋年FE）、`city_id` クラスターSE。

### 4.1 期間分割：δ の符号は安定しない

`paddy_ratio` を市町村平均で固定（完全に時間不変）したスペック。水準項は市町村FEに吸収される。

| 期間 | n | heat | heat × paddy_ratio |
|---|---|---|---|
| 1993–2000 | 3,165 | -0.00195 | **-0.00162 (0.00059)\*\*\*** |
| 2001–2008 | 2,564 | -0.00053 | **+0.00099 (0.00057)\*** |
| 2009–2020 | 2,884 | -0.00227 | -0.00029 (0.00044) |
| 全期間 | 8,613 | -0.00109 | **-0.00165 (0.00035)\*\*\*** |
| 1993年除外 | 8,214 | -0.00025 | -0.00087 (0.00033)\*\*\* |

**符号が期間で反転する。** 全期間の推定値は符号の異なる部分期間の平均であり、1993–2000 に牽引されている。

近代期（2009–2020）の95%信頼区間はおよそ $[-0.0011, +0.0005]$。平均 heat ≈ 12日で評価すると、水田率 0→100% の差が収量に与える影響は **-1.3% 〜 +0.6%** に収まる。大きな効果は緩和方向・逆方向ともに棄却される（informative null）。

### 4.2 期間の効果か標本選択の効果か

`paddy_ratio` 水準項を含むスペックでの2×2分解：

| | n | cities | heat | heat × paddy_ratio |
|---|---|---|---|---|
| (A) 全期間・全市町村 | 8,613 | 455 | -0.00107 | **-0.00171 (0.00038)\*\*\*** |
| (B) 全期間・208市町村 | 5,069 | 204 | -0.00093 | **-0.00194 (0.00057)\*\*\*** |
| (C) 2009+・全市町村 | 2,884 | 262 | -0.00225 | -0.00029 (0.00042) |
| (D) 2009+・208市町村 | 2,242 | 201 | -0.00287 | +0.00026 (0.00060) |

**期間の効果であり、標本選択の効果ではない。** 同じ208市町村でも、全期間なら $\hat\delta<0$、2009年以降なら $\hat\delta\approx0$。

（(A) は `research_plan2.md` の元の推定を対数化・クラスターSE化して再現したもの。`fixest` による元の結果 heat×paddy = -0.002\*\*\*、heat = -0.001\*\* と整合。）

## 6. 圃場整備率データ（農林業センサス）

### 6.1 データ構造

`Consolidation_data/GA0001_2014_2010_{08,09,10,11,12,13,14}.xlsx` = 農林業センサス農業集落カード「整備状況」表（2010年センサス、関東7都県）。

階層は PREF / CITY / KCITY（旧市区町村）/ RCOM（農業集落）。**`KCITY=='00' & RCOM=='000'` の行が市町村計**、`city_id = PREF + CITY` で `kanto.csv` と直結する。

| 列 | 内容 |
|---|---|
| 田（1ha以上）／（0.5〜1.0ha） | 大区画＝整備済 |
| 田（0.3〜0.5ha **ほ区均平**）／（**その他**） | 整備済／未整備の別 |
| 田（0.2〜0.3ha ほ区均平）／（その他） | 同上 |
| 農道_幅4m以上／3〜4m | 機械化対応 |
| **用水_田_パイプライン／開水路** | **灌漑方式** |
| 排水良好 | 乾田化 |

### 6.2 構築した変数

```python
SZ = ['田（1ha以上）','田（0．5～1．0ha）','田（0．3～0．5haほ区均平）',
      '田（0．3～0．5haその他）','田（0．2～0．3haほ区均平）','田（0．2～0．3haその他）']
m = d[(d.KCITY=='00') & (d.RCOM=='000') & (d.CITY!='000')].copy()
m['den']      = m[SZ].sum(axis=1)
m['consol30'] = m[SZ[0:3]].sum(axis=1) / m['den']      # 30a以上区画整備率
m['pipe']     = m['用水_田_パイプライン'] / (m['用水_田_パイプライン'] + m['用水_田_開水路'])
m['city_id']  = (m.PREF + m.CITY).astype(int)
```

| pipe | 0.307 | 0.325 | +0.174 | -0.085 | +0.032 |

### 6.5 2020年センサスは定義が異なる

```
2010年版: 田（1ha以上）(0.5-1.0ha)(0.3-0.5ha ほ区均平/その他)(0.2-0.3ha ほ区均平/その他)
```

## 7. heat の測定問題

| 統計量 | 値 |
|---|---|
| mean / SD | 8.92 / 8.85 |
| max | 39 |
| **heat == 0 の割合** | **18.6%** |
| within SD | 6.05 |
| between SD | 7.69 |

ゼロが約2割、右に長い裾を持つカウント変数。線形の当てはめには無理がある。

そして **within R² = 0.025**（`model.R` の全期間推定）。市町村FEと年FEを除去したあと、気象変数は収量の年次変動の2.5%しか説明していない。

現在の定義（7-8月の固定暦月、TMP_max ≥ 34℃の日数）は出穂・登熟期の年次変動を捉えられていない。**交差項が近代期でゼロなのが「本当に効果がない」ためか「heat の測定が悪すぎて検出できない」ためかは、現時点では区別できない。**

補足：断面で corr(TMP_mea, heat) = 0.703。スライド §6 の VIF 3.64 はこれに由来する。

## 8. 研究への含意

| 条件 | 状態 |
|---|---|
| $\hat\beta<0$（気象ショックIVの**関連性**の根拠） | **成立**。全スペック・全期間で頑健 |
| $\hat\delta>0$（`heat × 圃場整備率` IVの**除外制約**の根拠） | **未確認**。近代期で有意でない |

修論の識別戦略のうち、関連性の条件は問題なく満たされる。除外制約の農学的根拠については、現時点で実証的裏付けがない。

ただし「説明のつかない逆符号」よりは遥かに良い位置にある。$\hat\delta<0$ という異常を説明する必要がなくなり、残された問いは **「heat をきちんと測ったうえでも $\delta$ はゼロか」** の一点に収束した。

## 9. 次の一手

1. **標本期間・地域を設計文書に揃える**（関東5県・2001年以降 or 2009年以降）。1993年の冷夏を含めるか否かを明示的に決め、理由を記述する
2. **GDD で出穂日を推定 → 登熟期の気温ビン推定**（Schlenker & Roberts 2009 型）。判定基準は **within R² が上がるか**
3. 新 heat で `heat × consol30` / `heat × paddy_ratio` / `heat × pipe` の horse race を再実施
4. 千葉の2010年・2020年2波で整備率順位の安定性をチェック（時間不変仮定の検証）
5. それでも null なら、信頼区間を明示して **informative null** として報告する
6. 以降：`heat × 標高/傾斜/森林近接`、Conley 空間HAC標準誤差、interactive fixed effect

`analysis.py` 末尾に置かれた拡張案（interactive fixed effect / group structure panel / functional analysis）は、**heat がまともに測れていない段階では優先度が低い**。functional analysis はビン推定とテンソル積GAMで代替される。

### 閾値の選択について

同一データで閾値を推定してから同一データで $\beta,\delta$ に検定をかけると、post-selection により信頼区間が正しくない。実務的な落とし所：

- ベースラインの閾値は農学文献から取る（登熟期日平均26–27℃、日最高35℃）
- 推定閾値版（Hansen 2000 型の閾値回帰、プロファイル信頼区間つき）は頑健性として併記
